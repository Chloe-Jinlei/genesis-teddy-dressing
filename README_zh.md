# 四视角初始图像重建：给熊穿衣

本目录是一套基于四张初始图像的 **Genesis 理想化运动学穿衣原型**，用于探索操作流程与布料形变。衣片围住熊腹部，两只手臂分别穿过真实袖孔，两端贴条黏合后松开夹爪。布料由 Genesis 原生 PBD 求解，但机械臂执行、抓持和黏合采用了明显简化。

**这不是可直接迁移到真机的控制系统。** 最终报告中的 `task_success=true` 仅表示通过本项目定义的布料与几何代理检查，不能解释为机器人动作可执行，或整个机器人任务已被物理验证。它也不表示恢复了原仿真的真实几何、物性或动作。

## 已知机械臂控制问题

当前每步重新求逆运动学，并通过 `set_qpos()` 直接指定关节位置。虽然代码也调用位置控制接口，机械臂的实际执行并未由受动力学约束的控制器完成。逆运动学可能切换解支，保存的最终运行轨迹在约 **8.1 s** 和 **15.3 s** 处，分别出现单关节约 **165° / 20 ms** 和 **167° / 20 ms** 的跳变。这是动作轨迹不连续；提高视频帧率不能修复。

机器人碰撞关闭，关节速度、加速度和力矩没有纳入验收。抓持为单个布料粒子附着到手部，未模拟指尖接触、摩擦或滑脱；魔术贴为不带剥离和断裂模型的永久代理约束。现有验证器没有检查机械臂运动连续性，末端位置误差小也不能证明关节运动可行。

用于 sim-to-real 前，需要在仿真中先建立可执行的连续控制、机器人碰撞与抓持过程，并用真机可获得的观测重新验证任务。只在真机端替换控制模块，不能保证当前流程仍然成功。

## 输入与重建范围

观测输入只有用户提供的四张初始状态图片和上述任务描述。没有读取用户原仿真的模型、物性、控制器、动作序列或运行数据；没有读取项目 `sources/` 来补全这些信息。四张原始输入图未经编辑保存在 [inputs/initial_images/](inputs/initial_images/README.md)；原始文件名、仓库路径与 SHA-256 记录见 `input_provenance.json`。机器人复用了本地 Genesis 上游提供的 Panda URDF；熊、衣片、贴条纹理和场景摆放由本次代码重新生成。

四张未经标定的静态图不能唯一确定绝对尺度、相机参数、材料性质、接触状态或成功动作序列。因此，本模型是可检验的重建方案，不代表恢复了原仿真的真实参数或完整过程。

## 几何和物理假设

| 项目 | 当前建模方式 |
| --- | --- |
| 坐标与尺度 | 米制，+Z 向上，熊正面朝 −Y；桌面高度约 0.75 m，桌面约 1.40 × 0.95 m。尺度为图像推断假设。 |
| 熊 | 椭球部件组合，高约 0.455 m；躯干水平半轴为 0.132、0.100 m，赤道周长约 0.732 m。较宽的躯干是结合背面轮廓比例与贴条闭合需求选择的尺度先验。身体和手臂固定为刚体，没有识别毛绒柔顺性，手臂不会主动屈伸。 |
| 衣片 | 0.80 × 0.18 m 的连续三角网格，有两个真实袖孔；初始中心为 `(0, −0.28, 0.758)`。根据俯视图，局部袖孔中心分别为 `(-0.205, -0.045)` 与 `(0.205, -0.015)` m，沿衣片宽度错开 30 mm；+Y 为初始远边。孔名义尺寸为 0.066 × 0.068 m，以圆角矩形近似原图不规则轮廓。 |
| 布料 | Genesis 原生 PBD 拉伸、弯曲、重力和粒子自碰撞；粒子直径为 8 mm，面密度为 0.25 kg/m²。密度与柔度是显式假设。加载后会重新采样，验证使用实际求解器网格。 |
| 布料与熊、桌面 | 使用 Genesis 原生刚体耦合碰撞。该版本的 PBD–刚体接触实现未启用摩擦；设置 `coup_friction` 不能弥补这一点。布料粒子间自碰撞摩擦是另一项机制。 |
| 机器人 | 每步求逆运动学并通过 `set_qpos()` 直接指定关节姿态，执行预设轨迹加袖孔反馈；位置误差大于 2 mm 时回退为只约束位置的逆运动学，允许放松手部朝向。这不是受动力学约束的机械臂控制器，已知存在逆运动学解跳变，未约束速度、加速度或力矩。机器人碰撞与刚体互撞关闭。 |
| 抓持 | 初始抓取靠近观察者的两端边角，约为 `(±0.375, −0.357, 0.758)` m；每只夹爪仅用原生 `fix_particles_to_link()` 附着一个实际布料粒子。需要时换抓另一侧边缘，仍为每侧一个粒子；由 `release_particle()` 释放。这是理想化点附着，未建模夹持面积、夹持力或指尖摩擦。 |
| 魔术贴 | `native_seam.py` 预分配原生 PBD 距离约束，只有两端材料点足够近、相对速度足够低才激活。黏合后保留约束；没有剥离、断裂或真实黏合强度标定。 |

默认时间步为 0.02 s，每步 12 个子步；每子步最多进行 120 次拉伸迭代、3 次弯曲迭代，拉伸松弛系数为 0.1。这些数值控制求解过程，不能替代真实材料标定。生成网格的左袖孔与近边之间仅有约 7.5 mm 的连接带；程序和验证器检查实际加载后的拓扑，不能只依据生成前网格判断袖孔是否保留。

主程序的黏合距离阈值为 18 mm、相对速度阈值为 **0.015 m/s**。新增黏合仅允许发生在 12–14 s 或 19 s 之后的贴合阶段；已有黏合持续保留。约束静止间距默认等于粒子直径，即 8 mm，以避免与自碰撞厚度冲突。这里没有建立接触压力或真实钩环结构模型。模块支持额外法向门控，但当前主程序未提供法向。它使用 Genesis 1.4.3 私有边数组与求解器字段，升级 Genesis 后需重新检查兼容性。

当前主程序使用 `matching="contact"`：候选点对的初始衣片宽度方向坐标差小于 35 mm，运行时优先选择实际距离最近的合格接触，每个节点最多保留一个黏合。模块另保留 `matching="material"` 的预定点对模式。请用报告中的 `bonded_left_fraction`、`bonded_right_fraction` 查看两侧节点覆盖率；`active_fraction` 只是候选约束的使用比例，不能解释为黏合面积。

布料没有被逐帧强制设置成预制包裹形状。4–10 s 的袖孔反馈读取实际求解器中两个孔环的中心位置，按预定对孔目标积累有限幅的位置修正；10–12 s 逐渐衰减修正。这些修正只作用于机器人目标，布料其余形变来自原生求解器。

动作按照实际黏合状态选择是否换抓：

1. 抓住初始近边，抬起衣片，以袖孔反馈对准手掌并绕向熊背后。
2. 最早在 14 s、至少三个黏合激活后释放初始抓点。如果至少有 12 个黏合、世界坐标中的垂直跨度超过 12 cm，且两侧贴条各自沿原始衣片宽度划分的八个区间中至少六个有黏合，直接进入撤离与自由保持。
3. 若上述直接松手条件未满足，则移动到另一侧边角的实际位置；最早在 16 s 换抓，随后合拢下部贴条，19 s 起允许新增黏合。
4. 换抓后的最终释放最早在 21 s，并要求至少六个黏合、垂直跨度超过 7 cm。之后撤离并观察到默认 25 s。

释放门控只决定控制流程，不代替任务验收。视频阶段文字表示控制阶段，本身不是穿袖、包裹或黏合成功的证据。

## 接触求解调度

默认 `--contact-iterations 8` 启用本目录 `pbd_contact.py` 的局部调度适配器：将同一拉伸迭代预算分配到多轮原生自碰撞、刚体接触求解之间。例如 120 次拉伸迭代分为 8 轮、每轮 15 次；不能整除时向上取整，实际次数写入 `contact_solver.json`。使用 `--contact-iterations 0` 可运行 Genesis 原有顺序的基线。

该适配器调用现有 Genesis 内核，不修改已安装库的源码，不预设布料形状，也不改变粒子质量、静止长度、碰撞厚度或验收阈值。每个真实子步仅积分一次外力、重建一次最终速度，弯曲迭代预算保持不变。它只支持前向仿真、PBD 布料，以及参与耦合碰撞的固定刚体；运动的机器人链接仅驱动附着点，不参与接触。它仍依赖私有接口，不提供收敛保证、三角面级无穿透保证或可用的真实接触力标定。

## 运行

在具有 Genesis 1.4.3 的 Python 环境中运行；可通过 `GENESIS_PYTHON` 指定解释器。命令默认 CPU，可显式选择 GPU。渲染当前采用 EGL 与软件 OpenGL，独立于物理求解后端；首次编译可能较慢，缓存位于本目录 `cache/`。依赖包括 Genesis、NumPy、Pillow、imageio 及其视频编码支持。

最终示例运行使用 NVIDIA GeForce RTX 5070 Laptop GPU，PyTorch 为 `2.14.0+cu130`。若在容器或受限沙箱中运行，需要让执行环境能够访问 GPU 设备；宿主机有 GPU 不代表容器或沙箱内自动可用。

在本目录运行：

```bash
# 按最终运行的配置复现到新目录：31 秒仿真，25 fps 视频，逐主步保存状态。
./run.sh --backend gpu --duration 31 --render-every 2 --sample-every 1 --detail-video --contact-iterations 8 --output outputs/reproduced_final

# 对照：使用未经改动的原生接触求解顺序。
./run.sh --backend gpu --contact-iterations 0 --output outputs/my_native_baseline

# CPU 兼容模式。
./run.sh --backend cpu --output outputs/my_cpu_run

# 短运行检查；仍会保存初始、阶段和最终截图。
./run.sh --duration 2 --no-video --output outputs/my_smoke

# 每次完整运行结束会自动验证；也可独立重新验证保存的状态。
python validate_result.py --output outputs/reproduced_final
```

常用选项：

| 选项 | 默认值与作用 |
| --- | --- |
| `--backend cpu` / `gpu` | 默认 `cpu`；请求后端与实际 Genesis 后端、设备分别记录，不能只从命令推断是否真正使用 GPU。 |
| `--duration 25` | 仿真时长，单位秒。 |
| `--output outputs/my_run` | 输出目录；不同实验应使用不同目录，避免覆盖。 |
| `--sample-every 1` | 每个主时间步保存实际粒子状态与速度，默认约 50 Hz；不是每个内部子步都保存。 |
| `--render-every 5` | 每五个主步渲染一帧，默认视频约 10 fps；与数据采样频率独立。 |
| `--detail-video` | 额外保存 `close` 和 `back_close` 两个近景视角并排的视频 `details.mp4`。 |
| `--no-video` | 不写视频，仍保存数据、验证报告与多视角截图。 |
| `--viewer` | 开启本地窗口，需要可用的显示环境。 |
| `--particle-size .008` | PBD 粒子直径，单位米；改变它也会改变重采样网格与接触厚度。 |
| `--substeps 12` | 每个主步的子步数。 |
| `--stretch-iterations 120` | 每子步拉伸迭代预算。 |
| `--stretch-relaxation .1` | 布料和新增黏合约束的拉伸松弛系数。 |
| `--contact-iterations 8` | 默认启用上文适配器的八轮调度；`0` 使用原生顺序基线。 |

逐步状态与双视频会占用磁盘空间，复现时请使用新的输出目录并预留空间。

## 验证结果

请查阅对应运行目录的 `validation.json` 和 `metrics.json`，并结合多视角截图检查。`validation.json` 的 `task_success`、`failed_checks` 和各项限制说明共同解释布料与几何代理结果。`task_success` 不包含机械臂运动连续性、控制跟踪、关节限速、力矩或机器人碰撞检查；即便值为 `true`，已知的关节跳变仍然存在。

袖孔检查采用实际孔边界与固定手臂中心线的几何代理，穿透检查采用离散采样与椭球代理。验证还检查实际网格拓扑、原有布料边的拉伸、腹部覆盖、接缝覆盖与松手后的保持。默认逐主步保存数据能减少漏检短时变化，但仍没有记录每个内部子步。

外观也存在明确简化：袖孔的不规则轮廓由规则网格近似；熊由光滑椭球组合，未复原毛绒、软组织或精确关节结构；相机与光照没有标定；原图桌面散落的小棕色物体未复建，其用途未知。即使报告中的代理检查全部通过，也不证明原仿真等价、连续时间无碰撞、布料无自穿插、机器人轨迹可安全执行或真实魔术贴承载能力。
